# СМЭШ — Telegram Mini App. Спецификация для вёрстки

Версия 1.0 · 2026-10-15 · исполнитель: `frontend-designer`

Источник правды по визуалу — `../DESIGN.md` (токены, шрифты, шкала, компоненты, движение, запретный список).
Источник правды по экранам — Figma `k5e09t1rOr9tNNh5uYgqhe`, доска «СМЭШ — полный флоу», и скрипты `../work/src/*.js`: в них точные размеры, отступы и тексты всех экранов. **Figma MCP при вёрстке не вызывать** (лимит 20/мес): всё берётся из скриптов и `../screens-full.png`.
Этот файл описывает то, чего нет в макете: навигацию, Telegram, логику, состояния, данные, критерии приёмки.

---

## 1. Рамки

- Фронтенд мини-приложения на моках, без бэкенда. Данные живут в памяти + `localStorage`.
- Оплата фейковая: экран оплаты работает, деньги не списываются.
- Вход только через Telegram: пользователь берётся из `initData`. Экраны макета **04 «Вход» и 05 «Код из SMS» не верстаем**.
- Должно работать: внутри Telegram (iOS, Android, Desktop) и в обычном браузере с подменой Telegram (режим разработки, см. §3.8).

## 2. Стек

| Что | Чем | Почему |
| --- | --- | --- |
| Сборка | Vite + React 18 + TypeScript (strict) | быстро, статический билд для хостинга |
| Роутинг | `react-router` (HashRouter) | хеш-роуты переживают перезапуск мини-аппа и статический хостинг |
| Стили | CSS Modules + `tokens.css` с CSS-переменными из DESIGN.md | токены в одном месте, без рантайма |
| Анимации | `motion` (Framer Motion) | шиты с drag, переходы между экранами, AnimatePresence |
| Иконки | `lucide-react` | тот же набор, что в макете |
| Шрифты | `@fontsource/unbounded`, `@fontsource/onest`, только нужные начертания + кириллица | self-host, без запросов к Google |
| Telegram | официальный `https://telegram.org/js/telegram-web-app.js` + свой тонкий хук `useTelegram()` | без лишних зависимостей, полный контроль |
| Состояние | React Context + `useReducer`, persist в `localStorage` | данных мало |

Список зависимостей выше — всё, что ставим. Новые пакеты — только с согласия пользователя (правило оркестратора).

## 3. Telegram-интеграция

### 3.1 Старт
- `Telegram.WebApp.ready()` сразу после первого рендера сплэша; `expand()` — на весь экран по высоте.
- `disableVerticalSwipes()` — иначе свайп вниз по карте и шитам сворачивает приложение.
- Fullscreen (`requestFullscreen`) **не используем**: верхняя шапка Telegram с «Закрыть / ⌄ / ⋯» остаётся, как в референсе пользователя.

### 3.2 Шапка: «Закрыть» и «Назад» — нативные
- Свои кнопки назад и свою шапку Telegram (пилюли «Close», «⌄ ⋯» из макета) **не рисуем** — это делает клиент Telegram.
- Корневые экраны вкладок (Корты, Брони, Игроки, Профиль) → `BackButton.hide()` → слева сверху Telegram показывает «Закрыть».
- Любой экран глубже → `BackButton.show()` → Telegram показывает «‹ Назад». Обработчик `BackButton.onClick` = шаг назад по правилам §4 (не всегда `history.back()`).
- Открытый шит (фильтры) тоже показывает «Назад»; нажатие закрывает шит, а не уходит с экрана.
- В макете на экранах 11 (корт), 06/07 (регистрация), 12 (оплата), 17 (матч) нарисованы круглые кнопки «‹» — **в коде их нет**. Кнопка «♡» на корте и «поделиться» на матче остаются.
- Хук `useBackButton(handler | null)`: экран объявляет своё поведение, хук сам показывает/прячет кнопку и снимает обработчик при размонтировании.

### 3.3 Главная кнопка действия — наша
- Нативный `MainButton` **не используем**: он не держит стиль (цвет ball, шрифт Onest Bold, высота 56). CTA — наш компонент `Button primary`, закреплён внизу над safe area.
- `BottomButton`/`SecondaryButton` Telegram тоже не используем.

### 3.4 Цвета шапки и фона
Цвет шапки Telegram меняем под верх экрана, чтобы не было полосы другого цвета:
- `setHeaderColor('#111210')` — экраны с тёмным верхом: сплэш, онбординг 02–03, главная 08, карта 09, корт 11, бронь подтверждена 13, открытые матчи 16, матч 17, профиль 18.
- `setHeaderColor('#F1EEE4')` — светлый верх: уровень 06, районы 07, оплата 12, брони 14–15.
- `setBackgroundColor('#F1EEE4')`, `setBottomBarColor('#F1EEE4')` (если метод есть).
- Хук `useHeaderColor(color)` на каждом экране. Смена цвета — без анимации, в момент начала перехода.
- Тему Telegram (`themeParams`, светлая/тёмная) **игнорируем**: у приложения своя палитра в любой теме. Проверить, что в тёмной теме Telegram ничего не «просвечивает».

### 3.5 Safe area и высота
- Высоту брать из `--tg-viewport-stable-height`, отступы — из `safeAreaInset` и `contentSafeAreaInset` (CSS-переменные `--tg-safe-area-inset-*`, `--tg-content-safe-area-inset-*`), фолбэк `env(safe-area-inset-*)`.
- Таб-бар и закреплённые CTA стоят над нижним safe area.

### 3.6 Пользователь
- Имя, фамилия, `photo_url`, `username`, `language_code` — из `initDataUnsafe.user`. Нет фото → инициалы в `PlayerAvatar` (как «АК» в макете).
- Приветствие на главной: «Привет, {first_name}».
- Валидацию `initData` на сервере не делаем (бэкенда нет) — пометить TODO.
- Телефон не запрашиваем. (Опция на будущее: `requestContact()` при первой оплате — для чека.)

### 3.7 Тактильный отклик (HapticFeedback)
| Событие | Вызов |
| --- | --- |
| Выбор слота, даты, чипа, сегмента, таба | `selectionChanged()` |
| Нажатие primary-кнопки | `impactOccurred('medium')` |
| Удар мяча на сплэше (500 мс) | `impactOccurred('medium')` |
| Бронь / присоединение успешно | `notificationOccurred('success')` |
| Слот заняли, ошибка | `notificationOccurred('error')` |
| Попытка выбрать занятый слот | `notificationOccurred('warning')` |

### 3.8 Прочее
- `enableClosingConfirmation()` — только на экране оплаты 12, выключать при уходе.
- «Позвать друзей» → `shareURL(link, text)` (диплинк `t.me/<bot>/app?startapp=booking_<id>`; имя бота — константа `BOT_URL`, пока заглушка).
- Диплинк `startapp`: `booking_<id>` → открыть бронь, `match_<id>` → открыть матч 17. Парсить `initDataUnsafe.start_param` на старте.
- «Добавить в календарь» → сгенерировать `.ics` и открыть через `openLink(dataUrl)`; если не открывается — скачать файл.
- **Режим разработки вне Telegram**: если `window.Telegram?.WebApp?.initData` пустой — подставить мок `WebApp` (пользователь «Аня Ковалёва», все методы — no-op с `console.debug`) и нарисовать сверху **dev-шапку 56 px**, имитирующую Telegram: слева «✕ Закрыть» или «‹ Назад» (по состоянию BackButton, кликабельна), справа «⌄ ⋯». Только в dev/браузере, в Telegram не показывается.

## 4. Навигация

### 4.1 Типы экранов
- **Tab root** — корень вкладки, таб-бар виден, BackButton скрыт.
- **Push** — проваливание внутрь, таб-бара нет (если не сказано иное), BackButton виден.
- **Sheet** — шит поверх экрана, BackButton закрывает шит.
- **Flow** — линейная цепочка (онбординг), BackButton — шаг назад по цепочке.

### 4.3 Правила
- **Старт**: сплэш показывается всегда, минимум до кадра 01c. Если есть `start_param` → сразу на нужный экран (стек: корень вкладки + целевой экран, чтобы «Назад» вёл в приложение, а не закрывал его). Иначе: `onboarded` в localStorage → `/courts`, нет → `/welcome/1`.
- «Пропустить» на онбординге → `/welcome/level` (уровень нужен для подбора матчей). Финал `/welcome/places` «Готово» → `/courts` с `replace`, онбординг из истории удаляется.
- После оплаты → `/booking/:id/success` с **replace** экрана оплаты: «Назад» с подтверждения ведёт в «Брони», а не обратно в оплату.
- Переключение табов не копит историю: у каждой вкладки свой стек; повторный тап по активному табу — скролл вверх / возврат к корню вкладки.
- Вход в 11/12/17 из любого места сохраняет «откуда пришли» в стеке вкладки.

### 4.4 Все кнопки и куда ведут

**08 Главная** — поиск (тап) → `/courts/map` с фокусом в поиске; кнопка фильтров → шит 10; дата-чип → перезагрузка списка на дату; «На карте» → 09; карточка корта → 11 (с выбранной датой); слот-чип в карточке («16:00») → 11 с предвыбранным слотом; колокольчик → тост «Уведомления скоро» (экрана нет).
**09 Карта** — пин → выделить (ball, scale 1,1), шит показывает карточку этого корта; тап по карточке → 11; «Списком» → `/courts`; фильтры → шит 10; шит тянется вверх до списка всех кортов (snap points: 30 %, 85 %).
**10 Фильтры** — все контролы мгновенно пересчитывают число на CTA «Показать N кортов»; «Сбросить» → дефолты; CTA → закрыть шит, применить; свайп вниз / BackButton → закрыть без потери изменений (применяются сразу).
**11 Корт** — ♡ → в избранное (toggle, haptic); слот free → выбрать; busy → warning-haptic, ничего; длительность → пересчёт цены и доступности; дата (заголовок «Сегодня, 14 октября ⌄») → горизонтальный выбор даты; CTA «Забронировать» → 12. Без выбранного слота CTA неактивна с текстом «Выберите время».
**12 Оплата** — «Делим на 4 / Плачу целиком» → пересчёт суммы на CTA; способ оплаты (СБП по умолчанию); CTA «Оплатить N ₽» → лоадер 1,2 с → 13. С вероятностью 10 % (только в dev-флаге `?fail=1`) — «Слот только что заняли» → error-haptic, назад на 11, слот помечен busy.
**13 Подтверждение** — «Позвать друзей» → `shareURL`; «Добавить в календарь» → `.ics`; пустое место игрока (+) → тот же share.
**14/15 Брони** — сегмент «Предстоящие / Прошедшие»; билет → `/booking/:id` (вид 13 без заголовка «Корт ваш!», с кнопкой «Отменить бронь» если до начала > 6 ч — подтверждение через `showConfirm`); «повторить» в прошедших → 11 с тем же кортом, тем же временем и длительностью, на ту же дату следующей недели.
**16 Открытые матчи** — чипы-фильтры («Ваш уровень», «Сегодня», «до 5 км») toggle; «Присоединиться» (главный матч) → 17; карточка матча → 17; кнопка в карточке → 17.
**17 Матч** — «поделиться» → `shareURL` с `match_<id>`; «Присоединиться» → 12 в режиме матча (только доля, «Делим на 4» зафиксировано, сегмент скрыт) → 13 с текстом «Вы в матче!».
**18 Профиль** — «Уровень и районы» → `/profile/level` → `/profile/places`; «Способы оплаты», «Уведомления» → тост «Скоро»; **«Выйти» убрать** (вход через Telegram, выходить некуда); вместо него в dev-режиме — «Сбросить демо» (очистить localStorage, на сплэш).

## 5. Логика и данные

### 5.1 Моки (`src/data/`)
- `clubs.ts` — 8 клубов: Лужники Падел (Хамовники), Падел Раменки, Сетка Сокольники, Падел Пресня, Таганка Падел, Крылатское Арена, Строгино Падел, Марьина Роща Падел. Поля: id, name, district, metro, address, rating, distanceKm, mapX/mapY (координаты на нашей SVG-карте), courts[].
- Корт: id, number, indoor (крытый/открытый), features («Панорамное стекло»), tariffs: `{ day: 2400, evening: 3200 }` ₽/ч (вечер — с 18:00, выходные — evening весь день).
- Слоты генерировать детерминированно (seed = courtId + date): шаг 30 мин, 07:00–23:30, ~30 % занято.
- `matches.ts` — 8 открытых матчей на ближайшие 3 дня, уровни 1,5–5,0, 1–2 свободных места.
- `user` — из Telegram + `rating: 3.4`, история рейтинга за 3 мес (12 точек), 38 матчей, 61 % побед, 52 часа.
- Брони пользователя: 2 предстоящие, 5 прошедших (как в макете 14–15).

### 5.2 Правила
- **Цена** = тариф(час начала) × длительность/60. Длительность 60/90/120.
- **Доступность старта**: слот доступен, если все 30-минутные отрезки на длительность свободны и конец ≤ 24:00. При смене длительности недоступные слоты становятся busy-вида, выбранный сбрасывается с тостом «На 120 мин это время занято».
- **Прошедшее время сегодня** — не показываем.
- **Делим на 4**: доля = ceil(сумма / 4 / 10) × 10. Подтверждение: «Вы оплатили X ₽ · Ждём от игроков Y ₽».
- **Номер брони**: `SM-` + 5 цифр.
- **Отмена**: бесплатно, если до начала > 6 ч («Бесплатная отмена до HH:MM»).
- **Уровень**: 5 вариантов (Новичок 1,0–2,0 / Любитель 2,5–3,5 / Продвинутый 4,0–5,0 / Турнирный 5,5–6,5 / Профи 7,0). Матч «подходит», если рейтинг пользователя в диапазоне матча; иначе на 17 — плашка «Уровень матча выше вашего» и CTA всё равно активна.
- **Фильтры** по умолчанию: сегодня, «Любое» время, до 5 000 ₽, любой корт, районы из онбординга.

### 5.3 Сеть
- Все «запросы» — async-функции с задержкой 400–700 мс (имитация API), чтобы были видны скелетоны. Слой `src/api/` — готов к замене на реальный бэкенд.

## 6. Состояния (обязательно для каждого списка/экрана)
| Состояние | Как выглядит |
| --- | --- |
| Загрузка | скелетоны формы контента (`line` на `paper`, пульс 1,2 с), не спиннер. Исключение — CTA оплаты: спиннер в кнопке |
| Пусто: нет кортов по фильтрам | схема корта линиями `line`, «Ничего не нашли», кнопка «Сбросить фильтры» |
| Пусто: нет предстоящих броней | билет-контур пунктиром, «Пока без игр», primary «Найти корт» → `/courts` |
| Пусто: нет матчей по уровню | «Матчей вашего уровня нет», «Показать все» (снять фильтр) |
| Ошибка сети | тост снизу (ink, 3 с) + «Повторить» |
| CTA неактивна | `line` фон, `muted` текст, без тени, подпись-причина («Выберите время») |
| Офлайн | тонкая полоса сверху «Нет сети», данные из кеша |

Тосты: компонент `Toast`, ink-плашка, 13–15 px, снизу над таб-баром/CTA, 3 с.

## 7. Движение
Всё из `DESIGN.md → Движение` (кривая `cubic-bezier(0.22, 1, 0.36, 1)`, 150 / 250 мс, сплэш по таблице). Дополнительно:
| Что | Как |
| --- | --- |
| Push вперёд | новый экран: x 24 px → 0 + opacity 0 → 1, 250 мс; старый: opacity → 0, 150 мс |
| Назад | зеркально |
| Смена таба | crossfade 150 мс, без сдвига |
| Шит | снизу, 250 мс; drag с инерцией, закрытие при смещении > 30 % или скорости > 500 px/с; фон-затемнение ink 40 % |
| Нажатие кнопок/слотов/карточек | scale 0,97, 150 мс |
| Выбор слота | заливка ball, 150 мс |
| Сумма на CTA при смене длительности/деления | цифры перекатываются (roll), 250 мс |
| Подтверждение 13 | билет выезжает снизу 24 px + opacity, 300 мс; «Корт ваш!» — по словам, задержка 60 мс; success-haptic |
| Пустое место в матче | пунктирное кольцо вращается 12 с/оборот, линейно |
| Пин карты | scale 1 → 1,1, 150 мс |
| Скелетоны → контент | crossfade 200 мс |
| Сплэш | по таблице DESIGN.md; если данные готовы раньше — прыжок к 01c, если позже — держать 01c с прогрессом |
`prefers-reduced-motion` → всё заменяется opacity 200 мс, сплэш — статичный логотип 600 мс.
Анимировать только `transform` и `opacity`. Никаких анимаций height/top/left.
